# 并行智能体工作分配与发布门禁（2026-09-06）

## 调度结论

截至 2026 年 9 月 6 日，本轮协作上限为 4 个席位：1 个主协调席位、3 个并行子智能体。上一批任务已完成，当前采用“完成即轮换”；不能增加第 5 个同时运行的智能体。运行状态以协作面板最后心跳为准，不能用源码时间戳推断。为避免空闲，已将完成席位接续到 ACME 专项测试、网站真实验收矩阵和发布门禁收口。

本项目采用“多智能体开发、单智能体集成测试”的规则：开发智能体只处理自己负责的代码或文档，不执行全量测试、生产重启和前端构建；集成测试负责人统一执行测试并写入唯一测试记录。

## 当前角色与任务边界

| 角色 | 工作范围 | 当前交付物/出口条件 | 禁止事项 |
| --- | --- | --- | --- |
| 主协调智能体（`/root`） | 汇总冲突、审阅代码、发布/回滚、维护任务队列；当前优先网站/OpenResty/SQLite 上线闭环 | 只接收已通过集成门禁的变更；维护发布记录和阻塞清单 | 不重复跑集成负责人已完成的整批测试 |
| `https_enablement_review` | HTTPS/ACME HTTP-01、证书续期 hook、证书安装/回滚、OpenResty reload 安全性 | 证书状态与 SQLite/站点配置一致；续期后可自动同步并 reload；失败可回滚 | 不改参考前端；不执行全量测试或无备份生产破坏性操作 |
| `integration_test_owner_retry` | 唯一集成测试负责人；编译、race、vet、Node 契约、路由、SQLite、健康检查及发布后只读核对 | 更新 `progress/integration-test-latest.md`，明确 pass/fail/blocked/not-run；只此智能体执行全量门禁 | 不修改业务代码，不伪造外部资源结果 |
| `integration_website_retry` | 网站/OpenResty 契约与菜单映射审阅：从 1Panel 前端只读提取网站主/子菜单、接口变体、参数/响应字段；整理 Q2/Q5 测试矩阵和待测域名 | 产出脱敏路由/参数矩阵、设置项到配置文件映射、未具备凭据项的 blocked 原因 | 不执行全量 Go/Node 测试；不修改 `apps/1Panel/frontend`；不伪造 HTTP/WS 成功 |

若任一非测试任务提前完成，主协调智能体按 Q1-Q10 顺序轮换再分配；不得自行重复全量测试。所有测试证据统一交给 `integration_test_owner_retry` 收口。

## 唯一测试流水线

代码变更汇总后，仅由 `integration_test_owner_retry` 按以下顺序执行一轮：

```text
go test ./...
  -> go test -race ./...
  -> go vet ./...
  -> git diff --check
  -> Node 合约测试与 1Panel 路由扫描
  -> SQLite 只读完整性
  -> /health、/ready、systemd、OpenResty
  -> 有凭据时才执行登录后 HTTP/WS 和真实资源验收
```

任一门禁失败时，测试负责人停止后续依赖门禁并在集成记录中写明首个失败点；开发智能体只修复该失败点，修复后由同一测试负责人从受影响的最小前置门禁开始重跑，不能由多个智能体各自跑一遍。

## 发布和回滚出口

只有以下条件同时成立，主协调智能体才可部署最新后端制品：

1. 普通 Go 编译、race、vet、契约扫描和差异检查通过；
2. SQLite 迁移在真实运行库上幂等，且有主库/WAL/SHM/配置/旧二进制备份；
3. `/health`、`/ready` 和 OpenResty 配置检查通过；
4. 已执行的真实业务项有脱敏证据，无法执行的项明确标记 `blocked`/`not-run`；
5. 新制品 SHA-256、部署时间、systemd 状态和回滚路径写入发布记录。

前端源码没有变更时不得重新编译前端；`apps/1Panel/frontend` 永远只读。任何真实外部资源（管理员会话、Docker、次节点、DNS/ACME）缺失时，保留阻塞状态，禁止使用模拟 JSON、固定成功响应或假空数据填充测试结果。
